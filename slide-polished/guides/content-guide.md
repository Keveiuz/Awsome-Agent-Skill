# 内容创作指南

> **核心原则**：幻灯片是演讲的视觉锚点，不是演讲稿的文字副本。  
> 每一张页面应让观众听完这段话后觉得「我听懂了，我能给别人再讲一遍」，而不是「我抄了一堆关键词但不知道它在说什么」。

---

## 一、叙事弧原则（每页讲一个完整故事）

每张内容页都应遵循：**为什么 → 是什么 → 所以呢** 的叙事结构。

| 层级 | 作用 | 对应 HTML 元素 |
|------|------|--------------|
| **标题** | 说出结论，不是主题词 | `slide-title` |
| **副标题** | 给出数字或范围，限定上下文 | `slide-subtitle` |
| **卡片标题** | 命名这一论点（"问题/原因/方案/证据"） | `card-title` |
| **卡片正文** | 用 1–2 句话把论点讲清楚，可加类比 | `card-body` |
| **引言块/结论块** | 全页核心结论，用一句话收尾 | `quote-block` |

**❌ 错误示范**（关键词堆叠）：
```
卡片标题：多步决策
卡片正文：POMDP · 信用分配 · 延迟奖励 · 轨迹级优化
```

**✅ 正确示范**（口语化叙述）：
```
卡片标题：为什么单步 MDP 不够用？
卡片正文：传统 RL 每步打分，但现实任务要连续决策 20–50 步才
          能看到结果——就像下棋时只能在终局才知道哪步走错了。
          多步 POMDP 允许模型规划完整轨迹，延迟奖励到任务完成后再结算。
```

## 二、双层表达（技术概念必须有直觉锚）

每引入一个专业概念，**立刻跟上一个直觉类比或具体例子**。两层缺一不可：

```
第一层（精确定义）：PRM 在每个推理步骤独立打分，
                   提供密集奖励信号（dense reward）。
第二层（直觉类比）：相当于老师逐题批改，而不是只看期末卷面总分——
                   学生能立刻知道哪步推错了。
```

写法规则：
- 定义句用**被动/陈述语气**，精确但不啰嗦
- 类比句以「相当于」「就像」「想象一下」等引导，用生活场景
- 两者之间不需要生硬过渡，紧接着写即可

## 三、信息密度校准（不空洞、不昏昏欲睡）

**目标区间**：观众在听演讲的同时，扫一眼幻灯片，能在 5 秒内抓到核心论点。

### 过稀（空洞）的信号：
- 卡片正文只有 5 个字以内，全是名词
- 同一页上 3 个以上卡片，每个正文都是关键词列表
- 数字没有对比基准（"准确率 82%"——比什么高？）

### 过密（昏昏欲睡）的信号：
- 正文超过 4 行，且行行都是新概念
- 一张页面出现 3 个以上专有名词首次登场
- 表格超过 6 行且每行都有注释

### 校准方法——"一页一洞见" 原则：
每张页面只允许存在**一个核心洞见**，其他内容都是服务于这个洞见的支撑。  
写完后问自己：「如果只让我说一句话总结这页，是哪句？」——如果找不到，说明内容太分散。

### 数字必须有上下文：

| ❌ 空洞 | ✅ 有力 |
|--------|--------|
| 性能提升 22% | MATH500 准确率 71% → 93%（+22%），超过人类专家平均水平 |
| 效率提高 3 倍 | GPU 利用率从 35% 提升到 92%，相当于省掉 2/3 的机器成本 |
| 近零到可用水平 | OSWorld 桌面控制：< 3% → 25–35%，跨过了"可以实际使用"的门槛 |

## 四、主动联网补充（知识缺口时必须搜索）

当满足以下任一条件时，**在写页面内容之前先使用 WebSearch 工具**：

| 触发条件 | 行动 |
|---------|------|
| 需要引用具体数字（准确率、倍数、年份）但记忆不确定 | 搜索原始论文或综述确认数值 |
| 提到具体方法名/模型名（如 ARTIST、Planner-R1）但不清楚其具体机制 | 搜索 arXiv 或项目主页了解细节 |
| 需要做对比表（传统方法 vs 新方法）但没有基线数据 | 搜索相关 benchmark 的已知 SOTA |
| 概念涉及最新进展（2023 年后的技术） | 搜索确认是否有更新数据 |
| 类比例子是否准确需要核实 | 搜索相关背景知识 |

**搜索结果的使用规则**：
- 直接引用数字时，在页面底部加 `source-line` 标注来源（论文名 + arXiv ID 或年份）
- 搜索到与预期不符的数字时，**以搜索结果为准**，不要坚持记忆中的数值
- 如果搜索无法找到可信来源，改用区间表述（"约 20–30%"）并注明"估计值"

## 五、口语化表达规范

幻灯片正文应写成"讲给朋友听"的语气，不是论文摘要。

**检验方法**：把正文大声读出来，如果读完觉得像在背课文定义——重写。

具体规则：

1. **主语人格化**：不写「该方法实现了…」，写「模型现在可以…」/「训练时…」
2. **量词具体化**：不写「大量训练步骤」，写「连续 50 步决策」
3. **被动转主动**：不写「奖励信号被延迟」，写「直到任务完成才给分」
4. **因果显性化**：不并列罗列特点，用「因为…所以…」或「这意味着…」串联
5. **拒绝名词叠加**：超过 3 个名词连续出现（"多步序列决策奖励分配机制"），必须加动词/解释性短语拆开

**示例对比**：

```
❌ 论文腔：
  异步 Rollout 机制通过解耦生成与训练进程实现 GPU 利用率最大化。

✅ 口语化：
  原来的做法是"生成完才训练，训练完再生成"——GPU 有一半时间在空转。
  异步设计让两件事同时跑：一边生成新轨迹，一边训练已有数据，
  GPU 利用率从 35% 提升到 90%+。
```

## 六、内容准备 SOP（每页完成前的检查）

写完一页 HTML 之前，过一遍以下问题：

- [ ] 这页的**核心洞见**是什么？（一句话说出来）
- [ ] 每个专业名词是否都有**直觉类比**？
- [ ] 所有数字是否有**对比基准**和**来源**？
- [ ] 正文读出来是否像**在给人解释**，而不是在背词条？
- [ ] 如果有不确定的数据，是否已经**联网核实**？
- [ ] 每张卡片的正文是否在 **2–3 句话**以内说完一个完整的论点？
